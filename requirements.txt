# Pinned dependencies for reproducible Docker builds.
#
# The Reticulum stack (rns / lxmf / nomadnet) ships frequently with tight
# inter-package version constraints. The versions below are a known-good
# mutually-compatible set — verify with `pip install -r requirements.txt`
# in a fresh venv before bumping any of them.

# Reticulum stack
# Rebumped to the current 1.3.x / 1.0.x / 1.2.x triple (2026-07-19).
# We had been holding at rns 1.1.3 / lxmf 0.9.4 / nomadnet 0.9.8
# after an earlier bump (2026-06-05) broke inbound link establishment
# to hosted NomadPortal sites — clients saw the announce, the link
# request landed and got accepted, then timed out at "waiting for
# RTT packet from link initiator" with logs flooding "No interfaces
# could process the outbound packet".
#
# Rationale for rebumping now: side-by-side testing this session
# showed MeshChat (which pins rns>=1.3.7, lxmf>=1.0.1) reaches
# destinations that NomadPortal (rns 1.1.3) can't — same machine,
# same LAN, same second, same peer. The gap between "MeshChat works"
# and "NomadPortal fails" is thus specifically the RNS/LXMF version
# delta. The 1.3.x inbound regression may have been fixed upstream
# since the 2026-06-05 pin, may have been misattributed originally,
# or may still be present — watch inbound link handshakes closely
# after redeployment. If they regress in a way that outweighs the
# outbound reliability win, revert this commit to restore the 1.1.3
# triple and pursue a different mitigation.
rns==1.3.9
lxmf==1.0.1
nomadnet==1.2.7
